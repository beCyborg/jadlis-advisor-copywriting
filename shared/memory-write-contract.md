# Контракт записи в память советов

Читать перед любой записью в `{MEMORY_DIR}`. Здесь — **как** писать; **что** писать задаёт
конкретный скилл совета.

---

## 1. Дефолт: обычный Write, ничего больше

Память — набор markdown-файлов в одной папке. Ни плагинов, ни CLI, ни внешних сервисов
не требуется:

- запись — tool `Write` (новый файл) или `Edit` (дописывание в существующий);
- каталоги — `mkdir -p` перед первой записью;
- пути — только внутри `{MEMORY_DIR}`. Ни один шаг совета не пишет за её пределы; если путь
  вычислился наружу, это дефект — остановиться и сказать об этом.

**Ничего не перезаписывать целиком.** Журналы и профили только дописываются: `Edit` с якорем
по последней строке раздела, а не `Write` поверх файла. Затёртая история убивает главный
вопрос ревью — что изменилось за квартал.

## 2. Куда что кладётся

| Что | Куда |
|---|---|
| Вердикт совета, готовый текст | `{MEMORY_DIR}/<Совет>/<имя>.md` |
| Строка о прогоне | `{MEMORY_DIR}/Журнал советов.md` (append-only) |
| Ставка и даты пересмотра решения | `{MEMORY_DIR}/Журнал решений.md` (append-only) |
| Профиль и журнал сессий одного совета | `{MEMORY_DIR}/Профили/<совет>.md` |
| Транскрипты звонков | `{MEMORY_DIR}/Звонки/` — только по явному подтверждению |
| Артефакты прогона | `{MEMORY_DIR}/_runs/<прогон>/` — удаляются после записи вердикта |

Подпапку `<Совет>` создаёт скилл через `mkdir -p` прямо в корне папки памяти — по подпапке
на совет, рядом с журналами.

## 3. Имена файлов

- Вердикт: короткое название темы, 3–7 слов, без `/ \ : # ^ [ ] |`. Коллизия (`ls` по папке) →
  суффикс « (2)».
- Никаких имён людей, названий компаний и номеров сделок в именах файлов. Имя файла видно
  в поиске, в списке недавних и в панели файлов — то есть там, где содержание показывать
  не предполагалось.

## 4. Структура записи

Вердикт кладётся в файл **как есть**, без пересказа: содержимое `council-verdict.md` из рабочей
папки прогона переносится дословно. Шапку добавляет валидатор по своему протоколу.

Запись в `Журнал советов.md` — одна строка на прогон:

```markdown
- 2026-01-31 · adv-product · Ценообразование подписки — поднять цену на 40 % и оставить старую когорту
```

Поле «исход» в журнале решений остаётся пустым до пересмотра: пустое поле лучше выдуманного.

## 5. Если папка памяти лежит в Obsidian-vault

Тогда доступны две необязательные вещи. Обе — «сделать, если работает; пропустить, если нет»,
ни одна не является условием записи:

- **Wikilinks.** `[[Имя заметки]]` ставить **только** на файлы, которые реально существуют
  в папке (проверить `ls`/Glob). Ссылок на несуществующее не создавать.
- **Callouts.** Уместны три: `> [!warning]` — риски и то, что вынесено на решение человека;
  `> [!info]` — пометки о деградации прогона (неполный кворум, отказ линзы); `> [!quote]` —
  дословные формулировки клиента или пользователя.

Никаких вызовов внешних CLI: их отсутствие не должно ломать запись.

## 6. Чего не делать

- не дублировать вердикт в другие папки и не сводить его в дайджесты;
- не заводить теги вида `#цены`, `#клиенты` — по ним материал ищется и группируется теми,
  кто его искать не должен;
- не удалять старые записи «для порядка»: ошибочный вердикт остаётся в журнале с пометкой,
  иначе совет не учится на своих промахах;
- не класть папку памяти в публичный git.
